# P0 CI Gates

`p0-foundation.yml` runs on every PR and relevant push without path filtering. It grants only `contents: read`, cancels superseded runs, pins every action to an immutable commit, installs from the frozen pnpm lockfile, propagates command exit codes, and does not use `pull_request_target` or production secrets. Every job derives `EXPECTED_DUSKY_SHA` from `github.event.pull_request.head.sha` on pull requests or `github.sha` otherwise, explicitly checks out that ref, prints expected and actual `git rev-parse HEAD` values, and fails before installation if they differ. Repository-policy regressions reject removal of the checkout ref, runtime SHA lookup, or equality assertion.

Checks are `repository-policy`, `legacy-inventory`, `contract-registry`, `customer-foundation`, `merchant-foundation`, `captain-foundation`, `admin-foundation`, `backend-foundation`, `cross-app-scenarios`, and `build-readiness`. `legacy-inventory` checks out public MyPetNew evidence separately at exact SHA `817c6487cdbf18fc282dc0a44538d83e7bc5ef8b` and verifies tracked hashes; it validates committed metadata for local-uncommitted evidence without claiming access to that content. `contract-registry` retains full history and passes `github.event.pull_request.base.sha` to the validator while still executing the PR head. Backend evidence includes real PostgreSQL Testcontainers execution and uploaded test/coverage reports. Build readiness exports each Expo web shell, builds Next.js production output, and creates the Spring Boot jar; it does not deploy. A run is exact-head evidence only after all ten job logs contain equal expected and actual SHA values.

Future CD must use protected environments, provenance-attested immutable artifacts, environment-specific migrations with backup/rollback evidence, separate deploy identities, post-deploy readiness/smoke checks, and explicit user-approved promotion. P0 provisions none of these services.
